# Dépannage G7, ONE+ {#g7-one-troubleshooting}

Si ce n'est pas déjà fait, consultez d'abord [comment configurer le G7/ONE+](../install/g7). Beaucoup des causes décrites ci-dessous sont les mêmes que pour le [G6/ONE](./g6) : la force du signal et la batterie y sont traitées, et nous y renvoyons plutôt que de les répéter.

## Dépannage pas à pas {#step-by-step-troubleshooting}

Si xDrip est réglé pour collecter directement depuis un G7/ONE+ mais ne reçoit pas de données, suivez ces étapes dans l'ordre :

1. Désactivez le [Mode développeur](../use/misc#engineering-mode).
2. Désinstallez l'application Dexcom, ou toute autre application qui se connecte directement au capteur.
3. Vérifiez le capteur lui-même : voyez-vous le filament dépasser sur le dessus ? Si oui, prenez-le en photo pour Dexcom : même une fois connecté, le capteur ne donnera pas de valeurs exploitables puisque le filament n'a jamais vraiment été inséré sous votre peau, et il vous en faudra un nouveau.
4. **« Missing QR Code » sur la page Dex Status** : utilisez Paramètres → Configuration automatique pour scanner le QR code du [guide de configuration](../install/g7#setup-xdrip), et non un code imprimé sur le capteur lui-même, puis appuyez sur **Redémarrer le collecteur** dans la page d'état classique.
5. **« Mismatch - wait » sur la page Dex Status** : vous avez probablement mal saisi le code d'appairage, ou des capteurs déjà utilisés se trouvent à proximité. Éloignez les capteurs déjà utilisés de plus de 10 mètres, vérifiez le code d'appairage par rapport à celui imprimé sur l'applicateur, puis appuyez sur **Redémarrer le collecteur**.
6. **Vérifiez la connectivité** : s'il n'y en a aucune, utilisez un [scanner Bluetooth](./g6#how-strong-is-the-transmitter-signal) pour vérifier si l'émetteur est seulement visible, après avoir éloigné les anciens appareils. S'il n'est toujours pas visible, approchez l'aimant de l'applicateur du capteur pendant quelques secondes (cela peut déclencher son activation), puis vérifiez à nouveau avec le scanner et appuyez sur **Redémarrer le collecteur**.
7. **« Deep Sleeping Errors », « Checking Auth Errors », « Scanning Errors » ou « Initializing Errors » sur la page Dex Status** :
    1. Notez l'ID de l'émetteur actuel à 4 chiffres depuis Paramètres.
    2. Remplacez son dernier chiffre par un autre.
    3. Désactivez la collecte dans xDrip, et désactivez temporairement toute pompe, tout récepteur ou toute montre connectés directement au capteur.
    4. Attendez 15 minutes que le G7 passe en [mode de reconnexion rapide](#g7-rapid-reconnect-mode).
    5. Supprimez les appareils Bluetooth nommés `DXCM*`, `DX01*`, `DX02*` ou `DX04*` de la liste des appareils connectés / précédemment connectés d'Android.
    6. Réactivez le collecteur Dex de xDrip (sélectionnez Dex comme source de données matérielle) et remettez l'ID de l'émetteur correct que vous aviez noté.
    7. Allez sur la page Dex Status, attendez jusqu'à une minute une demande d'appairage et acceptez-la ; si aucune n'apparaît, redémarrez le téléphone.
    8. Une fois connecté avec 3 valeurs consécutives, vous pouvez réactiver votre pompe, votre récepteur ou votre montre.
8. **« Sensor Failed 7 » sur la page Dex Status** : évitez de vous allonger sur le capteur et détendez le membre qui le porte, hydratez-vous bien et attendez jusqu'à 3 heures que les valeurs reviennent. Si les valeurs reviennent mais continuent de disparaître au hasard, consultez [Connectivité intermittente](./g6#intermittent-connectivity).

## Mode de reconnexion rapide du G7 {#g7-rapid-reconnect-mode}

En temps normal, un G7/ONE+ émet une fois toutes les 5 minutes, avec à chaque fois un échange d'accusés de réception dans les deux sens. S'il manque trois accusés de réception d'affilée (15 minutes sans échange réussi), il passe en mode de reconnexion rapide : il répète chaque valeur jusqu'à 4 fois de plus, une fois par minute, pour qu'une application qui se reconnecte n'ait pas à attendre un cycle complet de 5 minutes pour l'attraper. Cela dure jusqu'à 12 heures, ou jusqu'à ce que l'application se reconnecte, selon ce qui arrive en premier.

Dès qu'un échange réussit, les émissions supplémentaires s'arrêtent. xDrip lit l'horodatage de la valeur qu'il reçoit (qui correspond toujours au cycle sous-jacent de 5 minutes) : il se resynchronise donc correctement sur le rythme normal, même s'il a capté l'une des émissions supplémentaires de chaque minute plutôt que la « vraie ».

## Journaux de débogage OB1 {#ob1-debugging-logs}

Ceci s'applique aussi bien au G6, ONE, G7 qu'au ONE+ : ils utilisent tous le même collecteur OB1, qui n'enregistre que très peu de détails par défaut. Si un développeur vous demande des journaux détaillés pour dépanner un problème de connexion, activez d'abord la journalisation OB1 complète.

Le plus simple est de scanner ce QR code avec Paramètres, [Configuration automatique](../use/copysettings#auto-configure) et d'accepter l'importation. Il ne modifie qu'un seul paramètre, Balises supplémentaires pour le log.

Vous pouvez aussi saisir les balises à la main :

&emsp;[Paramètres moins courants](../use/lesscommon)

:::

::: xdripitem Balises supplémentaires pour le log
&ensp;Ob1G5CollectionService:v,Ob1G5StateMachine:v
:::

Ensuite :

- Attendez que le problème se produise réellement avant d'envoyer les journaux. Activer la journalisation seule ne capture encore rien d'utile.
- Ouvrez le [Journal des événements](../use/3dotsmenu#events-log) depuis le menu à 3 points, appuyez sur Télécharger les Logs et ajoutez une note identifiant l'appareil afin de pouvoir faire le lien lorsque vous signalez le problème.
- Désactivez-la ensuite : videz le champ Balises supplémentaires pour le log et validez. Sinon, elle continue à générer un gros volume de journaux supplémentaires.
